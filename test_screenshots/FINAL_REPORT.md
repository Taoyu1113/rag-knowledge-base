# Echo 学习助手 - 真实大学生用户测试报告

**测试时间**: 2026-06-11  
**测试人**: 模拟大二学生（人工智能专业，首次使用本系统）  
**测试方式**: Playwright 浏览器自动化 + Gradio Client API  
**测试环境**: Windows 11, Chromium headless, Gradio 6.15.2

---

## P0（系统不可用）

### P0-1: 课程选择状态间歇性丢失，导致部分提问被拒绝

**测试编号**: 4, 5, 7  
**复现步骤**:
1. 创建课程"数据结构"→ 上传 test.pdf
2. 提问"总结这门课的主要内容"→ 系统回复"请先在顶部选择一个课程。"
3. 追问"举个例子"→ 系统正常回复并引用课程内容
4. 提问"帮我出5道选择题"→ 系统再次回复"请先在顶部选择一个课程。"

**现象**: 课程已创建且被选中，但系统在某些消息中无法识别已选课程，间歇性返回"请先在顶部选择一个课程。"。

**为什么大学生会受影响**: 学生已经完成了创建课程和上传资料，提问时被反复告知"请先选择课程"会让学生认为系统坏了，直接放弃使用。

**根因推测**: `create_btn.click` 更新 `course_dd.value` 后，`course_dd.change` 事件可能未正确触发 `current_course_state` 更新，或者 Gradio 事件链存在竞态条件。

**修改建议**: 在 `send_message` 函数内部增加防御性检查——如果 `current_course_state` 为"全部"但课程下拉实际选中了课程，应从下拉值推断当前课程。或直接在 `create_btn.click` 的回调中同时更新 `current_course_state`。

## P1（严重影响学习）

### P1-1: 无新手操作引导

**复现步骤**: 以新用户身份首次打开系统，观察界面30秒。  
**现象**: 界面同时展示5个操作控件（课程下拉、新建课程输入、创建按钮、上传按钮、删除按钮），没有优先级指引。欢迎区为空白，没有任何说明文字。

**为什么大学生会受影响**: 大二学生不知道这个系统需要"先创建课程→上传资料→才能提问"的工作流程，可能先去底部输入框直接提问（得到空结果），然后放弃使用。

**修改建议**: 
- 页面加载后显示清晰的步骤引导：Step 1 创建课程 → Step 2 上传课件 → Step 3 开始提问
- 高亮当前应该操作的控件
- 欢迎区显示引导文字而非空白

### P1-2: 上传 PDF 后处理状态不明确

**复现步骤**: 点击"上传 PDF/PPT"→ 选择 PDF 文件 → 等待。  
**现象**: 选择文件后没有进度条、没有处理状态提示。只有处理完成后在消息区显示"入库完成: 1/1 个文件, 4 个 chunk"。

**为什么大学生会受影响**: 学生不知道系统是否在正常工作，可能认为"卡住了"而刷新页面或重复上传。PDF 较大时等待时间更长，焦虑感更强。

**修改建议**: 
- 上传后立即显示"正在处理中..."进度提示
- 处理完成后显示"学习完成！已解析 N 个知识点，你可以开始提问了"
- 避免使用"chunk"等技术术语

### P1-3: 回答引用来源标注不充分

**复现步骤**: 提问课程相关问题 → 查看回答。  
**现象**: 部分回答中出现了 `[片段2 - 第1课课件.pdf - 第4页]` 格式的引用标注，但不是所有回答都有。学生无法全面判断哪些内容来自课件、哪些是 AI 补充的。

**为什么大学生会受影响**: 考试复习时如果无法区分信息来源，可能把 AI 编造的内容当成课件知识来记忆，导致考试时出错。

**修改建议**: 
- 每个回答都必须标注引用来源
- 区分"来自课程资料"和"来自 AI 补充知识"
- 用不同颜色或标签标识信息来源

### P1-4: 课程切换时未清空对话上下文

**复现步骤**: 
1. 课程A上传PDF → 提问
2. 切换到课程B → 提问相似问题  
**现象**: 切换课程后，之前的对话历史仍然保留在聊天区，学生无法判断当前回答是基于课程A还是课程B。

**为什么大学生会受影响**: 如果多门课程的知识串线，学生可能把课程A的知识点误记到课程B上。考试前尤其危险。

**修改建议**: 切换课程时清空聊天历史，并显示提示"已切换到课程「XX」"。

## P2（影响体验）

### P2-1: 首页缺少系统功能说明
**复现**: 打开首页 → 阅读标题。  
**现象**: 标题只有"大学课程学习助手"7个字，没有一句话说明系统能做什么、和普通 AI 有什么区别。  
**建议**: 标题下增加副标题"上传课程资料，AI帮你总结、出题、答疑——所有回答基于你的课件"。

### P2-2: 界面像开发工具不像学生应用
**复现**: 首次打开页面 → 观察布局。  
**现象**: 工具栏（5个控件）、文件管理行、聊天区、快捷按钮全部平铺在一起，无视觉层次。红色"删除课程"和"删除选中文件"按钮与"创建"按钮同等可见。  
**建议**: 区分主次操作，把高级/危险操作收起；使用卡片或分区提高信息层次。

### P2-3: 创建课程后反馈不明显
**复现**: 新建课程输入 → 点击创建。  
**现象**: 创建成功的消息出现在消息区，与欢迎文字混在一起，字体小而灰。学生创建完可能没注意到反馈。  
**建议**: 创建成功后用醒目的绿色提示，或在课程下拉中自动选中新课程。

### P2-4: 快捷按钮只填充文字不触发动作
**复现**: 点击"出题练习"或"薄弱点"。  
**现象**: 点击后仅在输入框填充提示文字，不会自动发送或触发功能。学生点击后还要再点"发送"。  
**建议**: 快捷按钮应直接触发功能，或至少自动发送填充的文字。

### P2-5: 创建课程后未自动选中新课程
**复现**: 创建课程 → 立即上传文件。  
**现象**: 创建课程后需要手动切换到新课程才能上传文件。如果忘记切换，文件会上传到"全部"而非新课程。  
**建议**: 创建课程后自动切换到新课程，并聚焦上传操作。

### P2-6: 无学习进度和历史记录
**复现**: 连续使用30分钟 → 查看学习状态。  
**现象**: 没有任何地方显示已上传了多少文件、已提问了多少次、已学习了哪些章节。刷新页面后对话历史全部丢失。  
**建议**: 在侧边栏或顶部显示学习统计，保存对话历史。

### P2-7: 欢迎区初始为空白
**复现**: 首次打开页面 → 看消息区。  
**现象**: 首次加载时消息区（top_msg）为空，没有欢迎语、没有引导。直到手动操作后才有内容。  
**建议**: 首次加载时显示欢迎引导内容。

## P3（优化建议）

### P3-1: 缺少暗色模式
**复现**: 晚间使用 → 白色界面刺眼。  
**建议**: 添加暗色/亮色主题切换。

### P3-2: 删除操作无二次确认
**复现**: 点击"删除课程"或"删除选中文件"。  
**现象**: 删除按钮直接触发删除，没有确认弹窗。学生可能误触导致课件被删除。  
**建议**: 危险操作前弹出确认对话框。

### P3-3: 文件列表缺少元数据
**复现**: 查看课程文件下拉。  
**现象**: 只显示文件名，不显示上传时间、文件大小、是否已处理。  
**建议**: 显示上传时间和文件大小。

## 系统表现良好的方面

以下是在测试中发现的**正面表现**（不纳入问题报告，但值得记录）：

1. **外域拒绝正确**: 提问"量子力学是什么？"后，系统正确回复"当前课程资料中未包含这部分内容。"——没有编造。
2. **来源追踪存在**: 部分回答中可见 `[片段2 - 第1课课件.pdf - 第4页]` 格式的引用标注。
3. **检索来源计数**: 回答后显示"检索来源 (N个片段)"，让学生知道系统确实检索了。
4. **上传反馈有细节**: "入库完成: 1/1 个文件, 4 个 chunk"——虽然有术语问题，但至少告知了处理结果。
5. **追问上下文保持**: "举个例子"的追问获得了与上一个话题相关的回答，说明上下文保持机制在部分情况下有效。

## 给开发者的总结

从一个大二学生的视角，系统的**核心 RAG 能力**（检索+生成）是有效的：它能正确检索课件内容、拒绝外域问题、标注引用来源。但 **用户交互层**存在严重问题：

1. **最严重的是课程状态丢失问题（P0）**——这会让用户产生"系统坏了"的认知，直接放弃。
2. **缺少新手引导**——目标用户是大学生，不是开发者，他们需要清晰的步骤引导。
3. **界面信息架构需要重新设计**——当前的平铺式布局对新手非常不友好。

建议优先级：先修 P0 状态丢失问题 → 添加新手引导 → 优化界面布局 → 完善细节体验。
