# 1. 项目定位

* **项目名称**: 个人学习知识库 (Personal Learning Knowledge Base)
* **项目目标**: 构建一个基于 RAG（Retrieval-Augmented Generation）的个人学习助手，支持上传 PDF 教材/课件，通过语义检索 + LLM 生成回答，帮助用户基于自建知识库进行问答学习。
* **主要用户**: 学生（个人用户），用于期末复习、课程知识检索。
* **当前应用场景**: 上传课程 PDF 资料 → 自动入库 → 按课程分类问答 → 获取带来源引用的 AI 回答。
* **当前项目类型**: RAG 知识库 + 学习助手（轻量级个人版）。

# 4. 当前项目流程

## 4.1 文档入库流程

```
用户选择 PDF 文件 (Gradio File Upload)
        ↓
pypdf.PdfReader 逐页提取文本
        ↓
text_clean.clean_text() 清洗文本
  · 去除控制字符
  · 统一换行格式
  · 去除乱码行
        ↓
chunker.chunk_text() 固定字符切分
  · CHUNK_SIZE=500 字符
  · CHUNK_OVERLAP=100 字符
  · 无句子边界检测
        ↓
embedder.get_embedding() 逐条向量化
  · DashScope text-embedding-v1
  · 含重试机制 (tenacity, max 3次)
        ↓
indexer.index_chunks() 存入 ChromaDB
  · Metadata: course, source(filename), chunk_index
  · collection.add() 逐条写入
        ↓
入库完成，用户可在 Web UI 查看统计
```

## 4.2 问答流程

```
用户在聊天框输入问题
        ↓
选择检索范围 (课程过滤 or 全部)
        ↓
embedder.get_embedding(query) 问题向量化
        ↓
ChromaDB collection.query()
  · 语义检索 (cosine 距离)
  · Top-K=5
  · 可选 course metadata 过滤
        ↓
得到 [docs, metas, scores] 各5条
        ↓
llm.generate(query, docs, metas)
  · build_prompt() 构造 Prompt
    - 包含 system prompt (角色+规则)
    - 包含参考文档片段（标注来源）
  · 调用 DashScope qwen-turbo
  · 含重试机制
        ↓
返回 LLM 回答 + 检索详情
        ↓
Gradio Chatbot 展示结果
```

# 7. 当前存在的问题

## 7.1 功能缺失

1. **Rerank 完全未实现**：`rerank.py` 为空文件，导致检索结果仅依赖 embedding 相似度，对专业性较强的教材内容检索精度不足。
2. **无对话记忆**：每次提问是独立的，用户无法追问"上一段提到的XX是什么意思"。
3. **无 Hybrid Search**：仅有语义检索，对专业术语、公式、代码等精确匹配场景表现差。
4. **无流式输出**：用户需等待数十秒才能看到完整回答，体验差。
5. **无查询改写**：用户输入口语化问题时无法自动改写为更精确的检索查询。
6. **Embedding API Key 硬暴露**：`.env` 文件中 API Key 明文存储，且 `.env` 虽在 `.gitignore` 中，但当前文件的 API Key 已经在代码中暴露（我方看到的文件内容即为实际 Key）。

## 7.2 架构问题

1. **ChromaDB 客户端重复创建**：`indexer.py` 和 `search.py` 各自独立创建 `client` 和 `collection` 实例（第10-14行完全相同），缺乏单例管理。
2. **无依赖注入/配置管理**：全局变量 `client`、`collection` 在模块导入时即初始化。
3. **无错误处理中间层**：API 调用虽有重试，但上层（`app.py`、`app_web.py`）无统一异常处理。
4. **无日志系统**：所有输出使用 `print()`，无法追踪问题。
5. **无异步支持**：所有 I/O 操作（API 调用、文件读取）均为同步阻塞。

## 7.3 检索问题

1. **固定 Top-K=5 不可调**：无法根据查询类型或文档库大小动态调整。
2. **相似度计算展示不精确**：`1 - distance` 对非归一化向量的 cosine distance 不等于 cosine similarity。
3. **无相关性阈值过滤**：返回所有 Top-K 结果，即使相似度极低也会传给 LLM，可能引入噪声。
4. **无去重机制**：相同或高度相似的 chunk 可能同时返回。

## 7.4 Chunk 问题

1. **固定字符数切分**：500字符一刀切，可能在句子中间断开，严重影响语义完整性和检索效果。
2. **无章节结构利用**：PDF 文本提取后丢失了所有章节/标题信息。
3. **无元数据继承**：chunk 不记录页码、章节名，无法定位原文位置。
4. **重叠策略粗糙**：100字符固定重叠不保证句子完整性。

## 7.5 Prompt 问题

1. **System Prompt 过于简单**：仅3条规则，无 few-shot 示例。
2. **无引用格式校验**：依赖 LLM 自觉遵守引用格式，无后处理验证。
3. **Prompt 模板硬编码**：未考虑不同场景（学术问答/概念解释/计算题）使用不同 prompt。
4. **无 token 计数/截断**：如果检索到的文档总长度超过模型 context 限制，会直接报错而非截断。
5. **LLM 模型使用 qwen-turbo**：不是最强大的模型，复杂推理能力有限。

## 7.6 UI 问题

1. **无响应状态反馈**：上传大 PDF 或等待 LLM 回答时无 loading 动画。
2. **消息不支持 Markdown**：LLM 回答可能包含 Markdown 格式但未被正确渲染。
3. **无对话历史持久化**：刷新页面或重启后对话消失。
4. **无移动端适配**。

6. **文件上传无进度条**。
