# UX 全面重构 — 设计文档

> 2026-06-08 | 决策者: yutao

## 目标

将当前"命令行风格"的学习助手改造为**纯聊天式交互**，消除斜杠命令的学习成本，新增对话记忆和知识点追踪，砍掉冗余功能。

## 核心决策

| 决策 | 选择 |
|------|------|
| LLM 模型 | `qwen-turbo`（省钱优先） |
| UI 框架 | 保持 Gradio，不换前端 |
| 后端架构 | 方案 B — Gradio + 服务化模块分层 |
| 课程总结/复习提纲 | 砍掉，只保留章节总结 |
| 知识点追踪 | 手动标记 (mastered / weak / unmarked) |
| 对话记忆 | 课程级持久化，跨会话保留 |
| 斜杠命令 | 保留作为兜底，不再作为主要入口 |

## 二、聊天交互流程

```
用户输入
  → Step 1: 上下文增强 (memory/tracker.py 注入课程+章节上下文)
  → Step 2: 意图分类 (router/intent_router.py, LLM 判断意图+提取参数)
  → Step 3: 执行功能 (调用现成模块)
  → Step 4: 记忆更新 (自动记录已学章节)
  → Step 5: 返回用户 (回答 + 折叠的检索来源)
```

### 意图类型

| 意图 | 自然语言示例 | 映射功能 |
|------|-------------|---------|
| `qa` | "第二章讲了什么"、"进程是什么" | RAG 问答 |
| `chapter_summary` | "总结第二章"、"第二章重点" | `generate_chapter_summary()` |
| `exam` | "出5道选择"、"给我出几道关于B树的题" | `generate_exam_questions()` |
| `explain` | "解释一下红黑树"、"什么是死锁" | `explain_concept()` |
| `mark_mastery` | "标记死锁为薄弱点"、"进程同步我学会了" | 更新 memory/tracker |
| `course_mgmt` | "上传一个PDF"、"有哪些文件" | 课程管理 |

### 意图分类 Prompt 设计

用 `qwen-turbo`，一次调用完成分类和参数提取，返回 JSON：

```json
{
  "intent": "chapter_summary",
  "chapter": "第二章",
  "question_type": null,
  "count": null,
  "concept": null
}
```

上下文注入当前课程名和已学章节列表，提高分类准确率。斜杠命令仍保留作为兜底（网络异常或 LLM 不可用时）。

## 三、记忆追踪系统 (`memory/tracker.py`)

### 存储结构 (`storage/course_memory.json`)

```json
{
  "操作系统": {
    "chapters_learned": ["第一章", "第二章 进程的描述与控制"],
    "mastery": {
      "进程的定义": "mastered",
      "进程同步与互斥": "weak",
      "死锁": "unmarked"
    },
    "last_active": "2026-06-08T15:30:00"
  }
}
```

### 三种行为

1. **自动记录已学章节**（静默）— 用户做章节总结/出题/解释时自动记录
2. **手动标记掌握度**（用户主动）— "标记死锁为薄弱点" → 更新 mastery
3. **影响检索和出题**（潜移默化）— 薄弱知识点出题概率 +50%，章节总结时标注 ⚠️

### 对话上下文注入

每次 LLM 调用前注入简短摘要（~几十 token）：

```
[系统上下文]
当前课程：操作系统
已学章节：第一章, 第二章
薄弱点：进程同步与互斥
```

## 四、UI 设计

### 布局：纯聊天

```
┌─────────────────────────────────────────┐
│ 📚 大学课程学习助手                       │
├─────────────────────────────────────────┤
│ 课程: [操作系统 ▾]  [+新建]  📎上传      │
├─────────────────────────────────────────┤
│                                         │
│  聊天区域（Chatbot 组件）                 │
│  所有交互在这里完成                       │
│                                         │
├─────────────────────────────────────────┤
│ [输入框...]                     [发送]   │
│ 快捷: [出题练习] [薄弱点] [上传文件]      │
└─────────────────────────────────────────┘
```

### 关键交互

- **欢迎消息**：首次打开或切换课程时，自动列出章节和建议操作
- **检索来源折叠**：默认 `📎 检索来源 (3个片段) ▸`，点击展开
- **三个快捷按钮**：点在输入框下方，填入提示文字而非直接执行
  - `[出题练习]` → 填入 "出5道关于"
  - `[薄弱点]` → 填入 "我的薄弱点有哪些"
  - `[上传文件]` → 触发文件选择器
- **📎 按钮**：输入框旁的附件按钮，触发文件上传
- **斜杠命令**：保留作为兜底，不在 UI 上宣传

| 功能 | 动作 | 理由 |
|------|------|------|
| 斜杠命令入口 | 降级为兜底 | 学习成本高，自然语言为主 |
| 课程总结 (`/总结`) | 删除 | 与章节总结雷同且太泛 |

| 知识点解释 | 保留 | 核心学习场景 |
| 智能问答 | 保留 | 基石功能 |
| 学习记录 | 替换为 tracker | 原实现无实用价值 |
| 知识点掌握追踪 | 新增 | 手动标记 + 影响出题 |
| 对话上下文记忆 | 新增 | 课程级跨会话持久化 |

| 课程管理（上传/删除） | 保留，简化 | 合并到聊天内 |

## 六、错误处理

### 意图分类失败

- LLM 调用超时/异常 → 降级为 `qa`（走正常 RAG 问答）
- LLM 返回无法解析的 JSON → 降级为 `qa`
- 斜杠命令作为最终兜底，不依赖 LLM

### 搜索无结果

- 不再只返回"未找到"，而是同时给出建议操作（切换课程/上传文件/换个说法）
- 如果目标章节不存在，列出当前课程已有章节

### 记忆存储异常

- `course_memory.json` 读写失败 → 静默降级，不影响主流程
- 损坏的 JSON → 备份后重建空文件

## 八、风险和注意事项

- **意图分类准确率**：`qwen-turbo` 在模糊输入下可能误分类，需在 prompt 中设定清晰的 fallback 规则（无法判断时走 `qa`）
- **Gradio 限制**：Chatbot 组件的定制能力有限，折叠来源、快捷按钮可能需要 workaround
- **存储迁移**：旧的 `learning_history.json` 需平滑迁移，不能丢失历史数据
- **向后兼容**：斜杠命令保留，确保降级路径
